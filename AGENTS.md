- Earnings entitlements come from organization declarations; bank receipts are separate user-owned confirmations, never inferred from allocations or company payment flags, to avoid confusing expected and received money.
- Onboarding loading must remain true for a newly signed-in user until that user's onboarding fetch settles, so post-login routing never uses the previous guest's empty state.
- Mission PDF generation consumes the mission page's calculated pools and allocations, separates third-party charges and reserves from people, and uses an export-only date/context brief with the mission's selected product; this prevents PDF calculations drifting from the live distribution.
- Organization distribution flows share shipped-product loading and selection, deriving mission title and iteration from active product delivery records rather than model usage; this keeps creation, editing, and export consistent with the Products tab.
- Activity Log uses server-authorized admin RPCs and server-derived authenticated actors/session boundaries; page tracking excludes auth screens, query strings, and conversation IDs to avoid sensitive content and spoofed return metrics. Existing click/event records are historical actions, not historical visit evidence.
- Business Evaluation uses the shared organization membership list and user/organization-scoped browser drafts; evaluation figures never update declarations, earnings, or legal records because they are self-reported assessments.
- Product Marketing Intelligence opens the newest saved analysis by creation date within the organization/product pair and asks for offer type only when none exists; failed lookups never create replacement pages, preserving access to saved research.
- Whether a project counts as finished/archived is decided by the single `isFinishedProject` helper in `src/lib/projectLifecycle.ts`, so project lists and pickers never disagree about archive state.
